# 답변 초안 스트리밍 (2026-10-17)

원자료는 `data/eval/reports/chat_pipeline/streaming-2026-10-17/`에 있다. 이 폴더는 Git 제외 대상이다. 통과 기준은 실행 전에 `PREREG.txt`에 적었다. 설계는 [설계 문서](../plans/2026-10-17-answer-streaming-design.md)에 있다.

## 1. 결정

| 항목 | 결과 | 적용 |
| --- | --- | --- |
| 분석을 쓰는 동안 초안으로 보낸다 | 첫 초안 중앙값 5.6초. 최종 답변 시간, 생성 실패, 초당 토큰 수는 그대로다 | 유지 |

## 2. 무엇을 바꿨나

- 웹 채팅은 답변을 끝까지 만든 뒤 한 번에 보여 줬다. 10-10 측정에서 첫 글자까지 중앙값 17.5초였다.
- 모델은 `analysis` 필드를 먼저 쓴다. 이제 이 필드를 쓰는 동안 화면에 초안으로 보낸다.
- 초안에는 "작성 중 · 검증 전" 표시를 붙인다. 검증을 마친 답변이 오면 초안을 바꿔 쓴다.
- 재생성이나 JSON 복구 재시도가 시작되면 초안을 지운다.
- `/v1/chat`은 그대로다. 평가 스크립트는 바뀌지 않는다.
- Ollama는 JSON 스키마를 지정해도 `stream: true`로 조각을 보낸다. 마지막 조각에 토큰 수와 시간이 있다.

## 3. 시험 1: 답이 바뀌는가

고정 근거 dev-80의 앞 20문항으로 시험했다. 온도 0, seed 7, 문항마다 세 번 호출했다.

| | 스트리밍 끔 (A) | 다시 끔 (B) | 켬 (C) |
| --- | ---: | ---: | ---: |
| 모델 호출 | 22 | 24 | 23 |
| 생성 실패 | 1 | 1 | 1 |
| 초당 토큰 (중앙값) | 52.7 | 52.7 | 52.6 |

- seed를 고정해도 같은 글이 다시 나오지 않았다. A와 B가 같은 문항은 20개 중 2개였다. 그래서 글 비교 대신 실패 수와 속도로 판정했다. 결과는 통과다.
- 초안을 이어 붙인 글은 파싱된 답 19개 모두에서 최종 `analysis`와 같았다.

## 4. 시험 2: 시간

백엔드만 띄웠다(8011). 10-10 시험의 웜 질문 30개를 두 엔드포인트로 번갈아 물었다.

| | `/v1/chat` | `/v1/chat/stream` |
| --- | ---: | ---: |
| 첫 초안 (중앙값 / 90백분위) | 없음 | 5.6초 / 7.0초 |
| 최종 답변 (중앙값 / 90백분위) | 16.5초 / 31.4초 | 16.5초 / 30.9초 |
| 오류 | 0 | 0 |

- 기준 "스트림 중앙값 − 일반 중앙값 ≤ 1.0초"를 통과했다(−0.06초).
- 30턴 중 초안을 지운 턴은 없었다.
- 10-10 기준선 17.5초는 10-15 Ollama 재설치 전에 잰 값이다. 그래서 같은 시간대의 `/v1/chat`과 비교했다.

## 5. 화면에서 확인한 것

- 초안이 흐르는 동안 입력창에 쓴 글과 포커스가 그대로 남는다. 처음에는 글자마다 화면 전체를 다시 그려 입력창이 새로 만들어졌다. 그래서 첫 조각에서만 다시 그리고, 그 뒤로는 초안 글자만 바꾸도록 고쳤다.
- 인용 괄호 `(S1, S2)`는 초안에서 지운다. 최종 번호 [1]은 답이 끝나야 정해지기 때문이다. 문장 안에서 이름처럼 쓴 `S1은`은 남긴다. 지우면 조사만 남는다.

## 6. 남은 한계

- 서버를 띄운 뒤 첫 실제 턴에서 모델이 분석 안에서 같은 말을 되풀이했다. 2,048토큰 한도에 걸렸고, 복구 재시도와 재생성이 이어졌다. 사용자는 3,949자의 초안을 약 38초 동안 보다가 그 초안이 지워지는 것을 봤다. 시험 2의 30턴에서는 이런 일이 없었다.
- 초안이 흐르는 동안 오른쪽 근거 패널에는 이전 답변의 근거가 남아 있다.
- 실제 서버에서 시험한 질문으로는 되묻기 턴이 생기지 않았다. 되묻기 턴에 초안이 없다는 것은 테스트로만 확인했다.

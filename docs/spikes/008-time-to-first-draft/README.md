# Spike 008 — 첫 초안 글자까지의 시간 (체감 지연)

날짜: 2026-11-24. 운영 구성(EXAONE 3.5 7.8B, bge-m3 CPU, fp16 리랭커), `scripts/serve.py` + `/v1/chat/stream`. 대화 ID는 새로 만들었고, 측정 뒤 저장소에서 지웠다.

## 측정 (`ttft-base.jsonl`, 최종 테스트 9문항)
웹 화면은 단계 문구(분석·검색·작성)를 먼저 보여 주고, 답변 `analysis` 초안을 글자 단위로 흘려보낸다.

| 시점 | 중앙값 | 범위 |
|---|---|---|
| 검색 시작 (= 질의 분석 끝) | 4.78초 | 1.39~6.00 |
| 작성 시작 (= 검색 끝) | 6.59초 | 3.44~7.85 |
| 첫 초안 글자 | 7.25초 | 3.71~9.93 |
| 응답 완료 | 21.1초 | 13.5~39.9 |

## 첫 초안까지의 구성 (서버 로그 `ollama_generation`)
- 질의 분석: 출력 150~250토큰을 디코딩하는 데 4~6초가 걸린다(입력 360토큰, 프리필 40ms). 뒤 단계가 쓰는 필드(열린 질문 등)를 만든다. 출력을 줄이는 안은 판단이 바뀌어 미채택했다(`data/eval/analyzer_slim`).
- 검색: 약 1.9초, 그중 리랭커가 1.5초다. 분석과 겹쳐도 GPU를 나눠 써서 줄지 않는다(`docs/spikes/007`).
- 답변 프리필: 증거 부분 약 1.3초(약 1,900 tok/s). 공통 시스템 프롬프트 800토큰은 분석 호출이 사이에 끼어도 Ollama 캐시에 남는다(`cache_probe.py`: 시스템만 보낸 호출 48ms, 서로 다른 질문 A·B의 프리필 1.26~1.31초).
- `legal_issues`가 `analysis`보다 먼저 나오는 필드 순서 때문에 약 0.3초를 더 쓴다.
- 30ms짜리 프리필은 앞선 측정에서 같은 질문을 물어 캐시에 걸린 결과다. 새 질문의 값이 아니다.

## 판단
품질에 영향 없이 줄일 곳은 남아 있지 않다. 캐시는 이미 동작하고, 병렬화는 GPU에 막힌다. 첫 초안을 앞당기려면 다음 중 하나를 바꿔야 하고, 모두 품질 평가가 필요하다.
1. 리랭커 후보 수: 첫 초안과 전체 시간 모두 최대 약 1초씩 줄어든다. 검색 정답 지표(gold S@10)로 잴 수 있다.
2. 분석 출력: 새 질문 세트에서 다시 사전 등록해야 한다.
3. 근거 길이(프리필): 답변 품질 평가가 필요하다.
4. 필드 순서(`analysis` 먼저): 약 0.3초 줄어들고, 답변 품질 평가가 필요하다.

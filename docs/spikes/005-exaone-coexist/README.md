# Spike 005 — EXAONE 3.5와 리랭커의 8GB 공존 (bge-m3 CPU)

날짜: 2026-11-23. 운영 설정·서비스는 바꾸지 않았다. 시스템 Ollama 0.40.4(flash attention 켜짐), RTX 4060 8GB(8,188MiB).

## 질문
운영 답변 모델은 qwen3:4b다(`.env`, `configs/local.yaml`). 품질 기준 모델 EXAONE 3.5 7.8B(Q4_K_M)는 bge-m3·fp16 리랭커와 함께 8GB에 들어가지 않는다고 봐 왔다. 질의 임베딩을 CPU로 돌리면 들어가는가?

## 결과 (`result.json`)

| 단계 | 결과 |
|---|---|
| bge-m3 질의 임베딩 GPU | 첫 호출 2.5초, 이후 0.01~0.03초, VRAM 0.59GB |
| bge-m3 질의 임베딩 CPU (`num_gpu: 0`) | 첫 호출 1.9초, 이후 0.04~0.05초, VRAM 0 |
| EXAONE 적재 (num_ctx 12288) | 5.84GB, 100% GPU, 2.4초 |
| + fp16 리랭커 100쌍 (max_length 512) | 최대 7,634MiB, 1.1~1.6초 (torch 할당 최대 1.24GB) |
| + EXAONE 프롬프트 8,285토큰 → 출력 261토큰 | 12.0초, 최대 7,642MiB, EXAONE 100% GPU 유지, 디코드 36.6 tok/s, 프리필 1,743 tok/s |
| 생성 뒤 리랭커 재실행 | 1.16초 |

## 판단
- 들어간다. 여유는 약 550MiB다.
- 질의 임베딩 CPU 비용은 질의당 약 +0.03초로 무시할 수 있다.
- 미측정: 동시 요청, 사용자 문서 임베딩(웹앱, 긴 텍스트)의 CPU 지연, 출력 2,048토큰까지 쓰는 경우, 웹앱과 API가 다른 bge-m3 옵션으로 부를 때의 재적재.
- KV 캐시 q8_0은 10-11 시험에서 qwen3:4b 기준 속도 이득 없음·품질 검토 실패로 채택하지 않았다. 이번 경로는 KV를 건드리지 않는다.

## 참고 지연 (같은 고정 근거 274문항, 생성 단계)
- EXAONE + 채택 프롬프트(2026-11-23): 중앙값 14.6초, p90 약 22초.
- qwen3:4b + 당시 프롬프트(2026-10-06): 중앙값 17.5초, p90 32~41초.
- 프롬프트가 달라 동일 조건 비교가 아니다.

# 필드별 부분 복구 설계

## 승인과 범위

사용자는 실패 필드만 선택 복구하는 다음 후보의 진행을 승인했다. 필요한 가역적 구현과 비교 시험을 수행한다. 기존 정상 생성과 표시 정책은 유지한다. 이전 core-first 후보는 포함하지 않는다. `.worktrees/partial-repair`만 수정하고 운영 활성화·커밋은 하지 않는다.

## 접근 선택

1. **정상 필드 보존 + 필요한 필드만 생성:** 출력량을 줄일 수 있다. 병합 뒤 전체 검사가 필요하다. 이번 후보다.
2. 인용 배열의 개별 항목만 수정: 더 작지만 항목 순서·삭제·중복 계약이 늘어난다. 이번에는 배열 전체를 한 필드로 수정한다.
3. 모든 오류에서 전체 답변 재작성: 현재 비교 경로다. 오류 위치가 불명확할 때의 fallback으로 유지한다.

## 구조화 오류

완성 JSON은 모든 필드를 개별 검증한다. 불완전 JSON은 맨 앞부터 완전히 종료된 최상위 값만 읽는다. 문자열·배열·객체를 임의로 닫거나 내용을 추정하지 않는다. 알 수 없는 키, 중복 키, 값 뒤 잘못된 구분자 또는 JSON 객체 외 출력은 부분 복구 대상이 아니다. 누락된 기본값 필드도 복구 대상으로 둬 자동 누락으로 의미를 지우지 않는다.

analysis가 완성·유효하지 않으면 기존 전체 JSON 복구를 사용한다. analysis가 있으면 정상 필드를 고정하고 누락·검증 오류 필드만 대상으로 둔다. summary가 유효하면 그대로 보존한다. confidence 오류와 citations 미완성도 독립 필드로 복구한다. 호출에는 기존 전체 근거·질문·이력과 검증된 고정 필드를 전달한다. 동적 스키마는 대상 필드만 필수로 요구하고 다른 키를 금지한다. 정확히 병합한 뒤 LegalAnswer 전체를 다시 검증한다.

## 인용 오류

완성 답변의 본문 필드를 그대로 둔 상태에서 citations만 비우고, 실제 전체 검증기를 같은 user_refs·own_clauses·prior_refs로 다시 실행한다. 이 검사에서 문제가 없을 때만 citations 배열 부분 복구를 허용한다. 본문에도 미확인 조문·사건번호가 남으면 기존 전체 재생성을 사용한다. 새 인용을 병합한 전체 답변은 기존 backfill·검증·재생성·strip·reject 정책을 다시 거친다.

## 실패와 표시

기본값은 field_repair=False다. 시험은 생성기 생성자에서만 활성화한다. 설정·웹 화면·API 스키마는 바꾸지 않는다. JSON 생성은 기존 최대2호출, 검증 재생성은 기존1회다. 부분 복구 호출 실패 뒤 추가 전체 복구 호출을 더하지 않는다. 준비된 답변·상태는 요청 지역 변수에만 둔다. 부분 필드·미완성 초안은 사용자에게 표시하지 않는다.

## 사전 비교 규칙

- 최초 실패가 같은 조건에서 복구 비용을 비교한다. 이전 fixed-failure의8개 JSON 실패 기록 전부와 answer-recovery main/baseline의 최초 검증 실패3개(index43,44,67)를 사용한다. 고유 질문/실패 개수와 겹침은 따로 보고한다.
- 11사례 ×2방식 ×2회차 =44측정턴. 회차·방식당1회 예열, 총4턴을 제외한다. 동일 고정 실패를 주입하고 실제 후속 모델 호출만 시간에 포함한다.
- 순서는 기존→부분복구→부분복구→기존. 두 번째 회차는 역순이다. 모델과 seed를 쌍 안에서 같게 둔다. 현재 model qwen3:4b/Q4_K_M, ctx12288, predict2048, temp0.2, think false, batch512, f16KV, FA, GPU37/37, parallel1을 유지한다.
- 이전의 최초 메시지와 제공 전체 근거를 두 방식 모두 동일하게 재현한다. 초기 주입 호출은 실제 추론 횟수와 분리한다. 정상 경로의 첫 요청 동일성은 별도 무추론 계약 검사로 확인한다.
- 속도 기준: 두 회차 모두 후속 전체 시간 중앙값10% 이상 감소, p90 비증가, 오류·거절·strip·재생성 비증가. 실제 부분 복구 사용 사례가 있어야 한다. fallback만 사용한 결과를 부분 복구 효과라고 하지 않는다.
- 모든 실제 payload·출력·스키마·완료 초안·검사·분기·최종·호출 수를 저장하고 기록에서 새로 재생한다. prompt_eval_count+2048<=12288, 서버 입력 절단/문맥 이동 없음, 모델·엔진 로그를 확인한다.
- 22쌍을 전체 근거·기존/후보 완료 답변·완료 초안·보존 필드와 대조한다. AI reviewed (Codex) 사유와 해시를 기록한다. 신규 의미 오류·필수 조건 소실·uncertain·완료율 감소는 채택을 막는다. 보존된 기존 오류도 따로 기록한다.
- 가짜 모델로 정상 경로·JSON 경계·잘린값·중복·미지키·배열·잘못된confidence·patch외필드·병합·호출상한·인용본문fallback·실제 정책·자료/사용자 격리를 검사한다. 기존 backend 회귀와 표시 경계 웹 회귀를 새로 실행한다.
- 운영 모델이 비어 있을 때 GPU lock 아래11435 소유 서버4개를 실행한다. 외부 모델 파일은 읽기 전용이며 운영 수동 unload/restart는 하지 않는다.

## 해석과 보존

측정 시간은 고정 실패 이후 생성·검사·정책 처리 시간이다. 최초 생성·검색·브라우저 대기 시간은 아니다. JSON/인용 검사 통과는 법률 의미 정확성의 증거가 아니다. 통과 여부와 무관하게 root443파일,이전15상태,외부9파일을 보존한다. 전체 지표와 보고서를 작성한 뒤 다음 채택 판단을 한다.

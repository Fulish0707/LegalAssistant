# 컨텍스트 실행 예산 시험 설계

기록일: 2026-10-11. 사용자 요청: 다음 지연 시험을 진행한다.

## 목적과 선택

같은 모델에서 `num_ctx` 12288과 10240을 비교한다. 큰 컨텍스트는 더 많은 메모리를 요구한다. 메모리 감소가 속도 개선으로 이어지는지는 측정해야 한다. 8192 후보는 과거 최초 입력 최대 6647 + 출력 예산 2048을 담지 못해 실행 전에 제외했다.

다른 선택은 KV 캐시 양자화 또는 별도 추론 엔진이다. 전자는 서버 설정 변경, 후자는 새 설치와 모델 형식 확인이 필요하다. 이번 후보는 기존 API의 요청 옵션만 바꾸므로 먼저 측정한다. 서버를 재시작하거나 모델을 명시적으로 언로드하지 않는다.

## 입력과 실행

- 현재 checkout 전체를 격리 worktree에 복사한다. 기존 변경과 9개 실행 상태는 보존한다.
- 개발 80문항에서 분야별 첫 문항 0/20/40/60, 과거 최초 입력이 가장 긴 43, 재시도 사례 2를 선택한다. 독립 시험 세트가 아니다.
- 별도 26번 문항을 블록마다 한 번 워밍업한다. 측정 24턴, 제외 워밍업 4턴이다.
- 1회차 기존→후보, 2회차 후보→기존의 ABBA 블록 순서다. 2회차 문항 순서를 역전한다.
- 동일 질문, 전체 제공 근거, 프롬프트, LegalAnswer 스키마, temperature 0.2, 출력 2048, think false를 유지한다. 같은 쌍의 seed는 같다.
- num_ctx는 최초와 재시도 요청 모두에 적용한다. 원래 JSON 수정·인용 재생성·최종 정책을 모두 실행한다.
- 설정별 워밍업으로 모델 로드 시간을 제외한다. 측정 안에서 발생한 재로드·재시도는 모두 시간에 포함한다. 강제 캐시 초기화는 하지 않는다.
- 모델 digest, API 버전, 블록별 /api/ps와 GPU 상태, 모든 요청·raw 출력·완성 초안·최종 답변을 기록한다.

## 판정

두 회차 모두 최종 생성·검사 중앙값이 10% 이상 줄고 p90, 호출 수, 오류, 거부, 인용 재생성·제거가 늘지 않아야 속도 신호가 통과한다. 출력 tokens/sec도 별도로 보고한다. 짧은 출력만으로 디코더가 빨라졌다고 판단하지 않는다.

최초 prompt_eval_count가 같은 쌍에서 같고, 모든 호출의 보고된 입력 + 요청 출력 예산이 해당 컨텍스트 이하인지 확인한다. 초과하거나 카운터가 없으면 입력 보존 기준을 통과하지 못한다. 이것은 카운터 기반의 제한된 확인이며 내부 토큰 전체의 독립 검증은 아니다.

12쌍의 질문·참고 답변·전체 제공 근거·두 최종 8필드·앞선 완성 초안을 AI가 읽는다. 새 중요 조건 손실, 잘못된 단정 또는 판단 불확실이 있으면 품질 기준을 통과하지 못한다. 인용 검사 통과는 법적 정확성 보증이 아니다.

파일·payload·정책 재생·기존 상태 감사를 마친다. 소규모 시험 결과만으로 서비스에 적용하지 않는다. 통과하면 확대 확인 후보로만 제시한다.

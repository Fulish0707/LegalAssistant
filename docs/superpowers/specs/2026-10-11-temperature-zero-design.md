# Temperature 0 시험 설계

## 목적과 후보 선택

답변 요청의 temperature 0.2와 0을 비교한다. 출력 변동성이 줄면 과도한 출력과 복구 호출이 감소하는지 확인한다. 정확도 개선이나 속도 향상을 미리 가정하지 않는다. 배치 증가는 앞선 시험에서 제외했다. 엔진·모델 교체는 설치와 가중치 변경이 필요해 별도 시험으로 남긴다. 이번에는 요청 옵션 하나만 바꾼다.

## 고정 조건

- 동일 qwen3:4b Q4_K_M 가중치, f16 KV, Flash Attention ON, GPU 37/37, parallel 1, num_batch 512.
- 컨텍스트 12288, 출력 2048, 전체 스키마, think false. 질문·참고 답변·검색/분석 스냅샷·5개 근거·프롬프트·JSON 복구·인용 검사·기존 최종 정책 유지.
- 문항 [0,20,40,60,43,2], 예열 26. 첫 요청 쌍의 유일한 차이는 options.temperature:0.2/0. 복구와 인용 재생성 호출에도 각 설정을 적용한다.
- seed = 2026101160 + round×100 + 원래 문항 위치, 후속 호출은 위치×1000 추가. 같은 seed로 토큰 동일성을 보장하거나 temperature 0의 완전한 결정성을 주장하지 않는다.
- 1차 temp02→temp0, 2차 temp0→temp02, 2차 문항 순서 역전. 24회 측정과 제외 예열 4회.

## 실행 경계

새 서버를 각 블록의 포트 11435에서 실행한다. 별도 모델 메타데이터, 원본 블롭 읽기 전용 참조, 다운로드·prune 금지, 공유 GPU 잠금을 사용한다. 운영 포트 11434에 활성 모델이 있으면 중단한다. 운영 서버를 재시작하거나 모델을 해제하지 않는다. 소유한 모델과 서버만 종료한다. commit 로그의 BatchSize512·f16·Flash Attention·전체 GPU 레이어와 /api/ps를 확인한다.

## 사전 판정

- 속도: 양 회차 중앙값 10% 이상 감소, p90·호출·전송 오류·거절·인용 재생성·제거 증가 없음.
- 입력: paired 첫 prompt count 동일, 예열 포함 모든 보고된 prompt count+2048≤12288, 입력 잘림 및 context shifting 없음. 내부 토큰 동일성의 독립 증명은 아니다.
- 품질: 질문·참고 답변·근거 전체와 12쌍의 최종 8필드·완료 초안·검사 결과를 대조한다. 새 중요한 오류 또는 uncertain이 있으면 실패. 기존 답변 오류는 분리한다. 입력은 이전 시험과 같으면 해시 비교 뒤 전체 읽기를 재사용하되 새 답변은 각각 새로 읽는다.
- 입력 평가 시간, 실제 호출별 디코딩 tokens/s, 문항별 출력량, 복구·인용 재생성 비용을 분리한다. cache slot의 접두부 사용량을 호출과 대조한다. prompt count/duration을 새 입력 토큰 처리량으로 표시하지 않는다.
- scope: 고정 분석·검색에서 생성과 최종 정책 처리까지. 브라우저 첫 표시나 검색 포함 전체 지연은 아니다. 개발 문항 6개, 별도 holdout·전문가 인증 없음. 통과해도 확대 확인 후보일 뿐 운영 적용하지 않는다.

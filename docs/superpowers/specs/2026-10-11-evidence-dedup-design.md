# 입력 근거 중복 제거 시험 설계

## 승인과 범위

사용자는 정확히 같은 원문을 한 번만 전달하고 출처 연결을 유지하는 제안을 먼저 테스트하도록 승인했다. 기존 P1이 반영된 현재 코드가 기준이다. 평가용 wrapper만 격리 worktree에 추가한다. root 코드·설정, 기존 실행 상태, corpus/index, 최종 응답과 검사 정책을 보존한다. 커밋, 서비스 재시작, 강제 unload, subagent 사용은 하지 않는다.

## 후보

본문 전체가 byte 단위로 같은 source를 찾는다. 충분히 긴 본문(100자 이상)이고 대체 표기가 더 짧을 때, 첫 source의 Text를 유지하고 후속 source의 Text를 앞선 source의 원문 참조 표기로 바꾼다. 서로 다른 문서일 수 있으므로 모든 원래 source ID, 헤더, 순서와 문서 연결은 유지한다. 검증·응답에는 전체 원본 EvidenceBundle을 전달한다. 텍스트 계획의 `texts`와 `aliases`로 모든 source별 원문을 정확히 복원할 수 있어야 한다. 후보는 모델 입력 메시지만 바꾼다. 다른 출력 스키마, 프롬프트, 재시도, 표시 정책은 바꾸지 않는다.

부분 일치, 공백 정상화, 의미 유사도, 문장 요약, 대화 기록 압축은 하지 않는다. 부분 일치는 판례 인용이나 문장 연결이 다를 수 있다. 중복 없는 입력은 기존 payload와 byte 단위로 같아야 한다. 이것은 안전성에 제한을 둔 첫 실험이며 모든 중복 제거 가능성을 평가하지 않는다.

## 고정 시험

기존 frozen 개발 입력 80개 전체의 첫 5 hits를 기존 ContextBuilder(1500)로 생성하여 중복을 스캔한다. 같은 설정의 기존 8문항 실험 입력과 원문 일치를 확인한다. 동결 입력 80개 전체에 exact renderer roundtrip을 확인한다. 모델 추론 비교 문항은 결과 생성 전에 `[2,10,42,76]`으로 고정한다. 10은 전체 중복, 나머지는 부분 중복이 있지만 후보가 변경하지 않는 A/A 대조다.

두 방식 × 4문항 × 2회차 =16 측정 턴. 회차당 방식별 1 warmup, 총4턴은 제외한다. 문항별 paired seed, 교차 순서, 두 번째 회차 순서 반전을 사용한다. qwen3:4b digest를 기존 기록과 대조하고 context12288, temperature0.2, output2048, think=false, 기존 full 스타일을 유지한다. GPU lock을 사용한다. 기존 분석/검색을 고정하고 생성·검사·정책까지 측정한다. 첫 요청 payload와 후보·실행기·원문·설정을 추론 전에 해시로 고정한다. 실패도 분모에 포함하며 결과를 보고 재측정하지 않는다.

## 판정

기계적 검증: source별 원문 복원, 헤더/ID/순서, 전체 검사용 원문, 출력 schema, 기존 재시도 제한, 대조 payload 보존.

속도 신호: 변경 문항10에서 두 회차 모두 전체 처리10% 이상 감소하고 추가 호출/거부/오류가 늘지 않아야 한다. 네 문항 전체 중앙값/p90과 첫 호출·prefill·decode token/time도 별도로 기록한다. 각 회차의 변경 문항 표본은1개이므로 속도 기준 통과도 채택 근거로 충분하지 않다. A/A 대조의 변동은 실험 잡음의 참고이며 사후 보정하지 않는다.

품질: 8쌍 모두 질문·reference·전체 원문·최종8필드·모든 앞선 완성 초안을 읽고 AI reviewed (Codex) 사유를 기록한다. 조건·예외·판단 주체·법적 결론·인용 내용/출처의 새 중대한 오류나 확인 불가가 있으면 통과하지 않는다. 기존/공유 오류는 후보의 새 오류로 세지 않는다. 인용 검사 통과를 법적 정확성으로 주장하지 않는다. 소표본 개발 문항 pilot이며 통과해도 기본 서비스에 적용하지 않는다.

# 검색 후 행동 정책 파일럿

## 적용 범위

기존 검색 범위와 기본 대화 경로는 유지한다. `policy_scope`를 명시한 `lease_review_v1` 검토에서만 검색 후 정책을 실행한다. 공통 결정부는 `rag/action_policy.py`이며, 현재 의미 판정의 사실·근거 요구는 가상 임대차 검토의 `rent-deduction`과 `clause-explanation` 프로필로 제한한다. 임대차 밖 의미 판정의 일반화가 검증됐다는 뜻은 아니다.

새 판단은 첫 검색과 최종 문맥 구성 이후, 답변 생성 이전에 들어간다. 기존 생성 후 인용 검증을 대체하지 않는다.

## 실행 경로

1. 명시적인 사건/쟁점과 요청 식별자를 검증한다.
2. 요청 입력 지문을 저장하고 동일 요청의 재실행을 방지한다. 완료된 같은 요청은 저장된 응답을 재생한다.
3. 기존 분석·검색·문맥 구성을 실행한다. 파일럿은 검색 전 되묻기로 조기 종료하지 않는다.
4. `SufficiencyAssessor`가 사용자 메시지·동일 사건/쟁점의 사용자 발화·이번 첨부 발췌·최종 법률 문맥을 구별해 읽는다.
5. 모델이 반환한 사실·법률 지원을 원문 위치와 대조한다. 필수 항목 누락·중복·가공 인용·엉뚱한 출처는 판정 실패로 처리한다. 원문에 인용문이 있다는 검사는 의미적 지지의 입증이 아니다.
6. 순수 결정부가 답변/되묻기/재검색/결론 보류를 고른다. 질문은 쟁점별 한 번, 추가 검색은 요청별 한 번이다.
7. 재검색은 기존과 같은 검색기·필터·문맥 상한을 사용한다. 새 결과와 기존 결과를 중복 제거해 문맥을 다시 만들고 그 문맥을 다시 판정한다. pinned 자료는 선두에 유지한다.
8. 답변을 만들면 기존 인용 검증을 거친다. 파일럿 답변에는 재질문 억제 지침을 제공하고 추가정보 질문 필드를 비우며 웹 질문 버튼도 억제한다.

## 입력과 응답

`policy_scope`: profile=`lease_review_v1`, matter_id=명시적인 사건 키, issue_id=`rent-deduction` 또는 `clause-explanation`.
`request_id`: 같은 요청의 재전송에서는 동일하게 유지한다. 같은 id의 다른 입력은 충돌이다. 식별자 변경을 멱등 재시도로 취급하지 않는다.

`withheld`는 정상적인 결론 보류 응답이다. `withheld.reason_code`가 `facts_unresolved`이면 중요한 사실이 남은 경우이고 `evidence_unresolved`이면 추가 검색 뒤에도 법률 근거가 부족한 경우다. `assessment_failed`는 판정 결과를 검증하지 못한 경우이며 사실이나 법률 근거가 없다는 뜻이 아니다.

보류 응답은 확인한 사용자 원문과 미해결 항목·한계를 설명한다. 새로운 법률 결론을 붙이지 않는다. 기술적인 검색/모델 통신/저장 실패는 정상적인 근거 부족으로 변환하지 않는다. 기존 `rejected`는 답변 생성·인용 검증 거절에 유지한다.

## 상태 보장과 한계

- 정책 테이블은 opt-in 실행 때 기존 대화 저장소의 SQLite DB에 별도로 생성한다. 기존 Turn payload 형식은 유지한다.
- 사건/쟁점별 대화 이력은 별도 내부 키로 분리해 다른 계약의 사실을 재사용하지 않는다. 자동 사건/쟁점 분리기는 구현하지 않는다.
- 질문·추가 검색 예산은 실행 전에 원자적으로 예약한다. 중간 실패가 발생하면 이미 예약한 예산을 되돌리지 않는 fail-closed 방식이다. 따라서 ‘최대 한 번 실행’과 ‘사용자에게 반드시 한 번 전달’은 다른 보장이다.
- 이미 실행 중이거나 실패한 같은 request_id를 새 실행으로 자동 전환하지 않는다. 프로세스 강제 종료로 남은 running 요청의 자동 복구/관리 도구는 이번 범위 밖이다.
- DB를 다시 열어도 같은 conversation_id의 상태는 유지된다. 기존 웹의 SERVER_START 기반 conversation_id 수명은 바꾸지 않는다. 웹 재시작을 넘어 같은 상담으로 이어진다는 보장은 없다.
- user_documents는 요청마다 전달된 발췌다. 발췌에 없다는 것을 원문 전체에도 없다는 뜻으로 해석하지 않는다. 처음 파일럿은 고정 가상 계약으로 발췌 문제를 통제한다.
- 인용 출처·원문 검사는 결정적 안전장치지만 충분성·적용관계의 의미 판단은 여전히 모델 의존이다. 자유문장 안의 재질문 부재 역시 별도 의미 평가 대상이다.
- `Trace.post_retrieval`에 정책 행동·이유·근거 묶음 버전·청크 ID를 남기고 기존 `Trace.policy_action`의 인용 검증 결과를 유지한다. 단계 지연은 기존 recorder로 측정한다.

## 판례 인용의 역할 확인

- 운영 판례 청크는 고정 길이 창이다. 제목으로 시작하는 청크가 없고 청크 헤더의 역할은 모두 "역할 미상"이다. 그래서 청크 헤더만으로 인용한 문장이 법원의 판단인지 당사자의 주장인지 알 수 없다.
- 판정은 `HybridRetriever.document_text()`로 인용한 청크의 문서 전체를 불러온다. 모델이 본 것과 같은 가림 처리(날짜·금액)를 문서에 적용하고 인용 위치를 찾는다. 그 위치 앞의 제목과 문장 표현으로 역할을 정한다(`legal_rag.chunking.quote_roles`). 문서를 찾지 못하면 청크만으로 정한다.
- 판례·결정례 인용은 역할이 판단, 법리, 역할 미상일 때만 근거로 인정한다. 당사자 주장, 열린 인용부호 안의 진술, 사실관계, 주문, 증거, 복수 역할은 근거로 인정하지 않는다. 법령은 확인하지 않는다.
- 각 인용의 역할은 `PostRetrievalDecision.support_roles`에 남긴다. 역할 미상을 근거로 쓴 비율은 이 기록으로 집계한다.
- 규칙은 표본 평가로 고정했다. 274문항 평가에서 실제 검색된 판례 문서 160개에서 문장을 뽑았다. 정답은 AI 표기자 2명이 서로 보지 않고 붙였고(kappa 0.93), 사람의 법률 검토는 없다. 평가용 100개에서 당사자 주장을 근거로 표시한 경우는 0/40(95% 상한 8.8%)이다. 근거로 표시한 문장 중 판단·법리인 비율은 85%로 사전 기준 90%에 못 미쳤다. 따라서 이 규칙은 주장 차단 필터로만 쓰고, 판단임을 보증하는 데 쓰지 않는다.
- 평가 뒤 한 가지를 더 엄격하게 바꿨다: `질의요지` 제목은 질의 기관의 입장으로 보고 차단한다.
- 정책이 답변을 고르면, 판단·법리로 확인되지 않은 판례·결정례 출처(역할 미상이거나 판정이 인용하지 않은 출처)를 생성 지시에 넘긴다. 지시는 그 출처만으로 결론을 단정하지 말라고 요청한다. 이 부분은 모델 의존이다.
- 최종 답변이 그런 출처를 실제로 인용하면 코드가 `uncertainty` 맨 앞에 고정 안내를 넣고 신뢰도 `high`를 `medium`으로 낮춘다. 해당 출처는 `Trace.unverified_case_sources`에 남긴다. 기본 대화 경로는 바꾸지 않는다.
- 가상 판결문 4사례 평가(`data/eval/action_policy_caselaw/RESULTS.md`, qwen3:8b·EXAONE 3.5 각 2회): 고정 안내는 답변 8건 모두 맞았고 주장만 있는 사례는 8/8 보류했다. 다만 기준 경로도 결론을 단정하거나 주장을 판단처럼 쓰지 않아서(블라인드 채점 0건), 단정 금지 지시의 효과는 이 사례로 측정되지 않았다. qwen3는 답할 사례 4/4를 판정 무효로 보류했다.
- 아직 하지 않은 것: 기준 경로가 실제로 틀리는 사례로 단정 금지 효과 측정, 판정률(58%)이 낮은 헌법재판소 결정의 처리, 새 표본으로 위험 오류율 재측정(근거 역할 약 120개 필요).
- 문서 전체 조회 지연은 운영 Qdrant에서 중앙값 5ms, 상위 10% 15ms, 최대 67ms였다(표본 160개).

## 실제 로컬 모델 행동 선택 (현재 코드)

2026-11-19, `6a4ccd5`에서 qwen3:8b와 EXAONE 3.5로 1회씩 실행했다(`data/eval/action_policy_pilot/runs/head-6a4ccd5-*`, `data/eval/action_policy_pilot_heldout/runs/head-6a4ccd5-*`). 같은 날 앞선 `live-local-*`, `heldout-*-v3` 실행은 인용 80자 제한이 들어가기 전의 미커밋 코드로 돌린 것이라 현재 코드의 결과가 아니다.

- 정책이 켜진 사례 18건(모델 2개 × 9사례) 중 기대 행동 순서와 일치한 경우는 0건이다. 정책을 끈 대조 사례 2건은 기본 경로로 답했다.
- qwen3:8b: 9건 모두 판정 무효로 보류했다(fail-closed).
- EXAONE 3.5: 판정 무효 3건, 행동을 잘못 고른 경우 6건이다. 6건 중 4건은 보류나 되묻기가 필요한 사례에서 답했다. 1건은 첨부 계약서에 있는 사실을 되물었다. 1건은 되묻기 대신 재검색 후 보류했다.
- 판정 무효 원인: 사용자 계약서를 법률 근거로 인용, 같은 항목 중복, 인용 불일치, 사실을 `missing`으로 판정하면서 근거 문장을 붙임(3건), 조항 설명 쟁점에 없는 사실 항목을 만듦(2건). 이 사례로 검증 규칙이나 프롬프트를 조정하지 않았다.
- 결론: 기반 구조와 결정적 안전장치(멱등성, 예산, 인용 대조, 주장 차단, 고정 안내)는 테스트와 실측으로 확인됐다. 그러나 의미 판정에 기대는 행동 선택은 로컬 모델에서 아직 쓸 수 없다. 특히 근거가 부족한데 충분하다고 판정하는 경우는 인용 대조로 막지 못한다.

## 로컬 검증 명령

저장소 루트에서:

```bash
env -u PYTHONPATH -u PYTHONHOME PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m pytest -q \
  tests/legal_rag/unit/test_action_policy.py \
  tests/legal_rag/unit/test_sufficiency.py \
  tests/legal_rag/unit/test_quote_roles.py \
  tests/legal_rag/unit/test_policy_state.py \
  tests/legal_rag/integration/test_action_policy_turn.py

env -u PYTHONPATH -u PYTHONHOME PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m pytest -q tests/
```

통제된 가짜 모델·검색 결과를 쓰는 통합 테스트는 실제 법률 판단 정확성이나 실제 검색 성능의 입증이 아니다. 실제 모델 비교는 별도 입력·실행 기록으로 보고한다. 기존 평가 문서의 과거 대규모 점수를 이번 정책 점수로 재사용하지 않는다.

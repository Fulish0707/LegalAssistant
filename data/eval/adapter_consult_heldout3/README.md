# 상담형 어댑터 규모 확대(v3 정답) 채택 확인 — 보류 평가 (사전 등록)

작성: 2026-11-21, 모델 실행 전. 결과를 본 뒤 기준을 바꾸지 않는다.

## 배경

v2(선별 52건)는 원래 어댑터보다 준비물·상황 반영·단정 회피가 올랐으나 16건 중 2건이 반복 루프로 잘려 완료율 게이트에 걸렸다(`../adapter_consult_heldout2/RESULTS.md`).
두 가지를 바꾼다: (1) 정답의 칸 사이 반복을 줄인 v3 틀형(주의점은 analysis에만, uncertainty는 짧은 일반 문장, 조치·추가 질문 중복 제거), (2) 학습 데이터 규모 확대(목표 100~150건, 같은 검수 기준·선별 전용).
52건 v3 정답 어댑터(A3)는 보류 세트 2에서 반복 진단용으로만 돌렸으며 채택 증거가 아니다.

## 입력

- 새 사례 8개: 임대차 2(XL1 차임 감액, XL2 임대차등기 협력), 민사 2(XC1 해제 의사표시 철회, XC2 수임인 선관의무), 형사 2(XX1 절도, XX2 공갈), 행정 2(XA1 불복 고지, XA2 정보공개 이의신청).
- 법령 8개 조문(공식 API 코퍼스): 민법 628·621·543·681, 형법 329·350, 행정절차법 26, 공공기관의 정보공개에 관한 법률 18. 이전 다섯 세트와 겹치는 조문이 없음을 빌더가 검사한다.
- 판결문 8개: 전부 가상(`실제 판례가 아님`), 근거 창은 판단 섹션. 대조표는 모델 실행 전 `scripts/build_adapter_heldout3.py`로 고정.

## 갈래·실행

- **E**: `exaone3.5:7.8b`. **A0**: `qwen3-4b-legal:q8_0`. **A4**: `qwen3-4b-consult-v4:q8_0` — 선별 100건 이상(완성형 v2 + 틀형 v3), 원래 어댑터에서 다시 학습, 3 epoch·lr 1e-4·누적 8, 검증 손실이 가장 낮은 epoch, 같은 Q8_0·비사고 템플릿.
- 구조화 갈래, 현재 운영 프롬프트, 운영 설정(temperature 0.2, max_tokens 2048, num_ctx 12288, timeout 300초, Modelfile 반복 억제 1). 사례당 2회, 단일 GPU 순차.

## 지표·채점

이전과 동일: A1/A2(치명)/A3 + C1~C6(`../answer_generation/GUIDELINES.md`). 48건 혼합 셔플(시드 20261126), 채점자 4명 × 12건, 블라인드. '해당 없음' 무효.

## 게이트 (v1·v2 평가와 같은 기준)

- 판정 1 — A4가 A0를 대체: H1 C3 비율 A4 > A0 그리고 C4 A4 ≥ A0 / H2 C1·C2·C5 각각 A4 ≥ A0 − 2 / H3 치명·인용 검증 실패 A4 ≤ A0, **완료 A4 ≥ A0**. 전부 통과.
- 판정 2 — A4가 EXAONE급(판정 1 통과 시): Q1 C1~C5 각각 A4 ≥ E − 2 / Q2 치명·인용 검증 실패 A4 ≤ E. 전부 통과.
- 판정 2 통과는 서빙 교체 후보일 뿐이다(Q4_K_M 패리티, 전체 파이프라인 공존 메모리 측정이 남음). 실패면 EXAONE 유지.

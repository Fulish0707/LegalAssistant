# 답변 생성 단계에 사용자 원문을 질문으로 넘기기 — 사전 등록

작성: 2026-11-25, 구현·측정 전. 운영 구성(EXAONE 3.5 7.8B, `configs/local.yaml`, `history_turns` 4). base는 이 커밋이다(정리 단계 지어낸 수량 검사 포함, 요약만 넘기기는 되돌린 상태).

## 배경
질문 정리 단계는 후속 질문을 독립 질문으로 다시 쓴다. 그런데 가끔 질문 모양 답변(QA)이나 답변(A)을 쓴다. 앞선 두 수정은 정리 결과를 고치거나 버리려다 실패했다(`data/eval/multiturn_fix`, `data/eval/condense_summary`). 바로 앞 실험의 새 세트에서는 44입력 중 6개가 결함이었다.

정리 결과는 세 곳에 쓰인다(`src/legal_rag/rag/orchestrator.py`).
- 첫 검색어
- 재정렬 질의
- 답변 생성 단계의 "질문"

이번 수정은 정리 결과를 바꾸지 않는다. 결함이 남아도 답변 단계로 번지는 피해를 줄이는 쪽이다. 그래서 정상 질문을 잘못 대체하는 경로가 없다. 사용자 원문을 검색어로 하나 더 넣는 안도 후보였으나, 사용자 결정으로 이번에는 이 수정 하나만 판정한다.

## 바꾸는 것 (한 가지)
설정 스위치 `rag.generate_from_message`. 켜면 답변 생성 단계의 "질문"으로 정리 결과 대신 사용자가 이번 턴에 쓴 문장을 넘긴다. 생성 단계는 지금도 이전 대화(최근 4턴)를 함께 받는다. 검색, 재정렬, 정리 단계는 바꾸지 않는다. 모델 호출 수는 같다. 기본값은 꺼짐이며, 꺼져 있으면 동작이 이 커밋과 같다. 채택하면 기본값을 켠다.

## 측정

### 사례 (이 커밋에 고정, 이후 바꾸지 않음)
`scenarios_heldout.json` T01~T40. 앞의 세트(M, N, P, Q, R, 손 사례 H)와 주제가 겹치지 않는다.
- T01~T30: 답변을 유발하는 두 턴(언제까지, 어디에, 얼마까지, 뭘 준비, 해도 되나요)
- T31~T34: 세 턴
- T35~T38: 앞 답변을 가리키는 후속 질문("말씀하신 방법", "그 절차", "거기에")
- T39~T40: 주제 전환

### 층과 순서
1. 기록(`run.py base`): 수정 커밋의 코드로, 스위치를 끈 채 T01~T40을 1회 실행한다. 정리 단계가 받은 메시지와 저장된 이전 대화를 기록한다.
2. 턴 재생(`replay.py`, 주 판정): 기록에서 정리 모델이 호출된 모든 입력에 대해, 그 이전 대화를 메모리 저장소에 넣고 턴 전체를 다시 실행한다. 조건은 세 개다.
   - base: 스위치 끔
   - base2: 스위치 끔, 한 번 더. 답변 모델 온도 0.2에서 생기는 흔들림을 잰다.
   - message: 스위치 켬

   조건 순서는 입력마다 돌린다. 분석·정리·검색은 온도 0이라 조건 사이에 같고, 답변 생성만 흔들린다.
3. 분류(`packet.py`). 분류자는 AI 작업자 둘이다. 각자 배정된 패킷 파일만 보고, 조건 열쇠(`-key.json`), 코드, 실행 기록, 다른 분류자의 결과는 보지 않는다. 사람 법률 검토는 없다.
   - 정리 분류: 입력마다 base 정리 결과를 Q, QA, A로 분류한다(기준은 `data/eval/condense_summary/PROTOCOL.md`와 같고 아래에 다시 적는다). 두 분류가 다르면 더 나쁜 쪽으로 정한다. A나 QA인 입력이 결함 입력 D이고, 나머지가 정상 입력 G다.
   - 짝 비교: 입력마다 base 답변과 다른 조건(base2 또는 message)의 답변을 "답변 1", "답변 2"로 보여 준다. 어느 쪽이 base인지는 무작위로 정하고, 분류자는 1, 2, =로 고른다. 두 분류자가 같은 쪽을 골랐을 때만 그 쪽의 승으로 세고, 나머지는 비김이다.
4. 판정: `score.py`.

### 정리 분류 기준 (분류자에게 그대로 준다)
정리 결과는 검색에 쓸 독립 질문이어야 한다.
- Q: 독립 질문이다. 이전 대화나 현재 질문에 있는 사실과 대상만 담는다. 가리키는 말을 풀어 쓰거나, 사용자가 말한 사실을 합치거나, 질문을 그대로 쓴 것도 Q다. 끝 괄호 보충, "알려 주세요"·"부탁드립니다" 같은 요청형도 Q다.
- QA: 질문 형태지만, 이전 대화와 현재 질문 어디에도 없는 답 내용을 담는다. 답 내용은 기한·기간, 절차·기관, 준비물·서류 목록, 법적 판단·결론, 법령명·조문이다.
- A: 질문이 아니다. 답변·설명·판단을 서술한 문장이 중심이다(물음표가 있어도 마찬가지).
- 판단이 어려우면 더 나쁜 쪽으로 분류한다.

### 짝 비교 기준 (분류자에게 그대로 준다)
두 답변 중 사용자의 현재 질문에 더 잘 답한 쪽을 고른다. 이전 대화의 맥락을 포함해서 판단한다. 다음 순서로 본다.
1. 사용자가 이번에 실제로 물은 것에 직접 답하는가. 다른 질문에 답하거나, 묻지 않은 것을 중심으로 쓰면 나쁘다.
2. 사용자가 말하지 않은 사실(날짜, 금액, 서류, 사건 경위, 이미 한 행동)을 사실처럼 전제하지 않는가.
3. 이전 대화의 맥락(누가, 무엇을, 어느 대상을)을 바르게 이어받는가.

법적 정확성은 판단하지 않는다. 길이나 문체로 고르지 않는다. 의미 있는 차이가 없으면 =를 고른다. 답변이 나오지 않은 쪽은 나온 쪽보다 나쁘다. 다만 나온 답변이 위 기준에서 크게 어긋나면 예외다.

## 판정 기준 (모두 만족해야 채택)
- G0 측정 가능:
  - |D| ≥ 6이어야 한다. 미만이면 "재현 부족"으로 적고 채택하지 않는다.
  - D에서 base2의 (승 − 패)의 절댓값이 2 이하여야 한다. 초과하면 "흔들림이 커서 판별 불가"로 적고 채택하지 않는다.
- G1 효과: D에서 message의 (승 − 패)가 max(3, ⌈|D|/3⌉) 이상이고, 패가 1 이하다.
- G2 정상 입력 보존: G에서 message의 (패 − 승)이 2 이하다.
- G3 안전: 재생 전체에서 다음 두 수가 각각 base + 1 이하다.
  - 답변이 나오지 않은 턴 수(`response_kind`가 answer가 아님)
  - 검증 실패 턴 수(`verification_ok`가 false)
- G4 지연: 재생 턴 시간 중앙값이 base + 0.5초 이하다.
- G5: 스위치 기본값을 켠 뒤 `env -u PYTHONPATH -u PYTHONHOME .venv/bin/python -m pytest` 전체가 통과한다.

## 멈춤 규칙
- 미통과면 스위치를 꺼 둔 채 남기지 않는다. 코드를 되돌리고 측정 기록만 커밋한다.
- 같은 세트로 고친 안을 판정하지 않는다. 검색어 추가 안은 이 세트로 판정하지 않는다.

## 한계
- 결함 입력은 실행 전에는 수를 모른다. 앞 세트의 비율(6/44)이면 7~9개로 작다.
- 분류자는 AI이고 사람 법률 검토는 없다. 짝 비교는 법적 정확성을 보지 않는다.
- 턴 재생은 기록된 이전 대화 위에서만 비교한다. 수정이 앞 턴 답변을 바꿔서 생기는 효과는 재지 않는다.
- 측정용 대화(`mt-<tag>-*`)는 기록 실행 뒤 `cleanup.py`로 백업하고 지운다. 턴 재생은 저장소에 쓰지 않는다.

# 후속 진단 (보류 세트 2, 채택 증거 아님)

작성: 2026-11-21. 이 세트는 이미 결과를 봤으므로 아래는 원인 진단이며 채택 판단에 쓰지 않는다. 최종 판정은 `../adapter_consult_heldout3/README.md`의 사전 등록을 따른다.

## 1. 정답 반복 축소(v3 틀형)만으로는 루프가 고쳐지지 않았다

- v3 틀형: 주의점은 analysis에만, uncertainty는 짧은 일반 문장, 조치·추가 질문 중복 제거(`--template-version 3`). 같은 선별 60건(학습 52·검증 8)으로 원래 어댑터에서 다시 3 epoch(16.7분, 검증 손실 0.849→0.426).
- 보류 세트 2에서 8사례×2회: **14/16 완료**(v2와 같음). 실패 2건은 WA1·WA2(근거가 긴 행정 사례)로, 분석 문자열이 반복되다 2048 토큰에서 잘렸다. 지연 중앙값 18.4→16.3초, 본문 길이 518→510자.
- 결론: 데이터 쪽 반복은 줄었지만 생성 루프의 원인은 디코딩에 있다.

## 2. 반복 억제(repeat_penalty) 탐침

- 루프가 났던 3사례(WA1, WA2, WL2) × 억제값 3종 × 4회 = 36회. 나머지 설정은 운영과 같음(temperature 0.2, num_predict 2048, num_ctx 12288, 스키마 제약).

| repeat_penalty | 유효 JSON | 잘림 | 본문 길이 중앙값 | 출력 토큰 중앙값 |
|---|---|---|---|---|
| 1.0 (현재) | 10/12 | 2 | 1,230자 | 693 |
| 1.05 | **12/12** | 0 | 1,090자 | 579 |
| 1.1 | 12/12 | 0 | 887자 | 505 |

- 표본이 작다(사례 3개). "잘림이 사라졌다"고 단정하지 않고, 억제값을 어댑터 서빙 설정에 넣고 사전 등록한 게이트로 판단한다.
- 부작용: 출력이 짧아진다(1.05에서 −11%). 준비물·읽기 쉬움에 영향이 있을 수 있어 게이트에서 함께 본다.
- 세 모델(EXAONE, 원래 어댑터, 상담 어댑터)의 Modelfile은 모두 repeat_penalty 1이었다. 어댑터에만 1.05를 적용하는 것은 모델별 서빙 설정 변경이며, 사전 등록 변경 기록에 남긴다. EXAONE·원래 어댑터는 그대로 둔다.

# 상담형 어댑터 v2 채택 확인 — 보류 평가 (사전 등록)

작성: 2026-11-21, 모델 실행 전. 결과를 본 뒤 기준을 바꾸지 않는다.

## 배경

v1(판결 질의응답 정답 + 추출 항목, 300건)은 보류 평가에서 두 판정 모두 실패했다(`../adapter_consult_heldout/RESULTS.md`): 판결 사실을 사용자 사건에 옮기고, 결론을 단정하고, 되묻지 않았다.
v2는 같은 실제 판결에서 **사용자 상황 질문과 상담 답변을 새로 작성**한 데이터(`scripts/build_consult_sft_v2.py`, 로컬 Qwen3-8B 초안 + 코드·판정 필터)로
**원래 법률 어댑터에서 다시** 추가 학습한다(v1 위에 쌓지 않는다). 사람 법률 검토 없음.

## 입력

- 새 사례 8개: 임대차 2(WL1 임차권등기명령, WL2 일부 멸실 차임 감액), 민사 2(WC1 동시이행, WC2 이행보조자), 형사 2(WX1 폭행, WX2 재물손괴), 행정 2(WA1 정보공개 결정기간, WA2 처분의 방식).
- 법령 8개 조문(공식 API 코퍼스): 주택임대차보호법 3의3, 민법 627·536·391, 형법 260·366, 공공기관의 정보공개에 관한 법률 11, 행정절차법 24. 이전 네 세트와 겹치는 조문이 없음을 빌더가 검사한다.
- 판결문 8개: 전부 가상(`실제 판례가 아님`), 근거 창은 판단 섹션. 대조표는 모델 실행 전 `scripts/build_adapter_heldout2.py`로 고정.

## 갈래·실행

- **E**: `exaone3.5:7.8b` (현재 서빙). **A0**: `qwen3-4b-legal:q8_0` (원래 어댑터). **A2**: `qwen3-4b-consult-v2:q8_0` (v2 어댑터, 같은 Q8_0·비사고 템플릿). epoch은 학습 데이터의 별도 검증 30건 손실이 가장 낮은 것.
- 구조화 갈래, 현재 운영 프롬프트, 운영 설정(temperature 0.2, max_tokens 2048, num_ctx 12288, timeout 300초). 사례당 2회, 단일 GPU 순차.

## 지표·채점

이전과 동일: A1/A2(치명)/A3 + C1~C6(`../answer_generation/GUIDELINES.md`). 48건 혼합 셔플(시드 20261125), 채점자 4명 × 12건, 블라인드. '해당 없음' 무효(대조표 비어 있지 않음).

## 게이트 (v1 평가와 같은 기준)

- 판정 1 — A2가 A0를 대체: H1 C3 비율 A2 > A0 그리고 C4 A2 ≥ A0 / H2 C1·C2·C5 각각 A2 ≥ A0 − 2 / H3 치명·인용 검증 실패 A2 ≤ A0, 완료 A2 ≥ A0. 전부 통과.
- 판정 2 — A2가 EXAONE급(판정 1 통과 시): Q1 C1~C5 각각 A2 ≥ E − 2 / Q2 치명·인용 검증 실패 A2 ≤ E. 전부 통과.
- 판정 2 통과는 서빙 교체 후보일 뿐이다(Q4_K_M 패리티, 전체 파이프라인 공존 메모리 측정이 남음). 실패면 EXAONE 유지.

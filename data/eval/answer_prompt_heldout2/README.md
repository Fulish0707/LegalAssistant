# 정교화된 답변 프롬프트 채택 확인 — 두 번째 보류 평가 (사전 등록)

작성: 2026-11-20, 모델 실행 전. 결과를 본 뒤 기준을 바꾸지 않는다.

## 배경

첫 지침 추가(`f2de53a`)는 준비물을 크게 개선했으나 보류 평가에서 주의점 회귀와 서류 이름 창작 부작용으로 게이트를 통과하지 못해 되돌렸다(`fc78d51`, 결과: `../answer_prompt_heldout/RESULTS.md`).
이번 지침은 실패 유형을 겨냥해 두 가지를 바꿨다(일반 규칙, 사례별 표현 아님):
1. 준비물: "거기서 확인되지 않는 서류·절차 이름을 만들어 내지 마세요" — 창작 금지 명시.
2. 주의점: "근거에서 확인되는 … 예외·기한·조건·요건은 빠뜨리지 말고" — 근거 한정 + 누락 금지 의무.

## 입력

- 새 사례 8개: 임대차 2(TL1 차임연체 해지, TL2 기간 2년), 민사 2(TC1 해제 원상회복, TC2 과실상계), 형사 2(TX1 상해, TX2 협박), 행정 2(TA1 사전통지, TA2 심판 집행정지). 이전 두 세트와 쟁점·법령이 겹치지 않는다.
- 법령 10개 조문: 공식 API 코퍼스에서 새로 추출(민법 640·548·396·763, 주택임대차보호법 4, 형법 257·283, 행정절차법 21·22, 행정심판법 30).
- 판결문 8개: 전부 가상(`실제 판례가 아님` 표시), 근거 창은 판단 섹션.
- 대조표: 모델 실행 전 빌드 스크립트로 고정.

## 갈래·실행

- old: 원래 프롬프트(되돌리기 커밋 `fc78d51` worktree). 실행 매니페스트에는 amend 전 해시 `d86aef8`이 기록되며, 두 커밋의 소스 트리는 같다(차이는 복원한 평가 기록 파일 2개뿐).
- new: 정교화 지침(현재 HEAD).
- 둘 다 exaone3.5:7.8b 구조화, 운영 설정(temperature 0.2, max_tokens 2048, num_ctx 12288, timeout 300초). 사례당 2회, 단일 GPU 순차.

## 지표·채점

이전 평가와 동일: A1/A2/A3 + C1~C6(`../answer_generation/GUIDELINES.md` 그대로, 대조표 대조). old/new 32건 혼합 셔플(시드 20261123), 채점자 4명 × 8건, 블라인드. 대조표가 비어 있지 않으면 '해당 없음' 무효(기준서).

## 채택 게이트 (전부 통과해야 채택, 첫 보류 평가와 동일)

- **G1 주효과:** C3 맞음 비율 new > old, C4 new ≥ old. (각 n=16)
- **G2 일관성:** C3 짝 비교 변화 ≥ 0인 채점자 3명 이상.

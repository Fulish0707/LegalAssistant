# 질문 정리 단계의 지어낸 수량 검사 — 사전 등록

작성: 2026-11-24, 구현·측정 전. 운영 구성(EXAONE 3.5 7.8B, `configs/local.yaml`, `history_turns` 4).

## 배경
질문 정리 단계(`QueryCondenser`)가 사용자가 말하지 않은 날짜·금액·기간을 질문에 넣는다. 정리 결과는 첫 검색어와 재정렬 질의가 된다. 프롬프트는 "사용자가 말한 사실, 숫자, 조문, 사건번호만 사용하세요"라고 지시한다.

개발 확인(`dev_scan.py`): 지금까지 기록된 정리 결과 52개(실행 4개)에서 지시를 어긴 수량이 있는 출력은 4개다.
- base N09 "9월 1일": 정리 프롬프트 예시 문장의 날짜다.
- fix N07 "2023년 3월", "500만원".
- fix 참고 M03 "2023년 3월 15일", "20일", "14일".
- 진단 M06 "2026년 3월 17일": 앞 답변에 있던 날짜다(사용자 사실이 아님).
나머지 48개에서는 걸린 수량이 없다. 사용자가 말한 수량을 옮겨 쓴 경우(M10 "500만 원", "1년")도 걸리지 않았다.
같은 스캔에서 조문 번호·사건번호 위반은 0개다. "…법" 형태 단어가 대화에 없던 경우는 1개(진단 M02 "근로기준법", 답변형 출력)다. N05 "교통사고처리특례법"과 M09 "민법 제626조"는 앞 답변에 있었다.

## 바꾸는 것 (한 가지)
정리 결과에서 수량을 뽑는다. 추출기는 `legal_rag.verification.quantities.extract_quantities`다. 대상은 날짜, 기간, 금액, 횟수, 비율이다. 뽑힌 수량 중 하나라도 사용자 메시지(최근 창 안의 사용자 턴과 현재 메시지)의 수량과 값이 다르면 정리 결과를 버린다. 비교는 차원과 기본 단위 값으로 한다. 따라서 "두 달"과 "2개월"은 같다.
  - 사용자 쪽은 관대하게 읽는다. 추출기는 "석 달째"를 서수로 보고 버리므로, 사용자 메시지에서는 "째"를 지우고 뽑는다. 또 정리 결과의 수량 표기(공백 제거)가 사용자 메시지(공백 제거) 안에 그대로 있으면 통과시킨다. 예: 사용자 "2025년 10월 1일"을 정리 단계가 "10월 1일"로 쓰면 추출기는 "1일"을 뽑는데, 이 표기는 사용자 메시지 안에 있다. 두 완화는 놓침만 늘리고 오탐은 늘리지 않는다.
- 조문 번호와 사건번호도 본다. 이전 대화 창(사용자와 상담 턴)과 현재 메시지에 없으면 버린다. 프롬프트가 허용하는 범위와 같다.
- 조문 없는 법령명은 보지 않는다. 개발 스캔에서 위반이 답변형 출력 1개뿐이었고, 법령명 목록 없이 정규식으로 뽑으면 "방법", "불법" 같은 오탐이 생긴다.
- 버린 경우에는 최근 창 안의 사용자 메시지와 현재 메시지를 공백으로 이어 검색어로 쓴다. 모델 호출은 늘지 않는다.
- 형식 검사(질문 형태, 근거 핸들)는 넣지 않는다. 앞선 형식 검사는 미채택이었다(`data/eval/multiturn_fix/RESULTS.md`). 이번에는 변수를 수량 검사 하나로 둔다.

## 측정
- 새 사례 12개(`scenarios_heldout.json`, P01~P12). 앞의 두 세트와 겹치지 않는다.
  - P01~P06: 사용자가 수량을 직접 말한다(1억 원, 두 달 전, 3년, 석 달째, 2025년 10월 1일, 200만 원, 6개월). 잘못 버리는지 본다.
  - P07~P10: 사실이 막연하다. 정리 단계가 수량을 지어내기 쉬운 형태다.
  - P11 세 턴, P12 되묻기 뒤 답하기.
- base는 이 사전 등록 커밋의 코드, fix는 수량 검사를 구현한 커밋의 코드다. **조건마다 2회 반복**한다(실행 간 흔들림이 컸다). 사례당 1회 실행을 4번 하는 셈이다. 순서는 base 1회, fix 1회, base 1회, fix 1회다.
- 기록과 자동 점검 K1~K4는 `data/eval/multiturn_fix`와 같다.
- 정리 결과 분류(작성자 1인이 원문을 읽음): 정리 모델의 원래 출력마다 "사용자 메시지에 없는 수량(날짜·금액·기간·횟수·비율)이 있는가"를 판정한다. 추출기가 못 읽는 표기("9월", 한글 수사 등)도 읽어서 센다.

## 판정 기준 (모두 만족해야 채택)
- G1 fix 2회의 최종 검색어 중 사용자 메시지에 없는 수량이 있는 것이 0개다(원문 판정).
- G2 fix 2회에서 대체가 일어난 턴 중, 원래 출력에 지어낸 수량이 없는 턴(잘못된 대체)이 2개 이하다.
- G3 K1, K2, K3, K4 각각, fix 2회 합계가 base 2회 합계보다 3개 이상 적지 않다(24개 중 base − 2까지 허용).
- G4 개발 확인 단위 테스트: 위 개발 스캔의 4개 출력을 버리고, 걸리지 않은 출력 중 사용자 수량을 옮긴 것(M10)과 수량 없는 것을 통과시킨다.

base 2회에서 지어낸 수량이 하나도 나오지 않으면 G1은 효과를 보여 주지 못한다. 그 경우에도 G1~G4로 판정하되 RESULTS에 그렇게 적는다.

## 한계
사례 12개다. 법률 검토는 없다. 원문 분류는 작성자 1인(AI)이 한다. 날짜 없는 "9월 1일"은 추출기가 "1일"(1일 기간)으로 읽으므로, 사용자가 다른 뜻으로 "1일"을 말했으면 놓친다. 수량이 맞아도 관계(이내·전·후)가 바뀐 경우는 보지 않는다.
